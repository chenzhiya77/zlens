# zlens

Local-first 的 AI Coding Agent token 用量与成本分析工具。v2 支持多数据源:
ZCode(`~/.zcode/cli/db/db.sqlite`)、MiniMax Code(`~/.minimax/v2/sessions`)、
opencode(`~/.local/share/opencode/opencode.db`),列表后续可扩展。

打开即查:总览(KPI + 模型明细,可为同名模型起别名区分)、用量分析(日趋势 /
按模型 / 按项目三个维度)、运行质量(耗时分位数 + 重试与错误)。多来源合并展示,
每行可追溯到来源;全程只读,不影响正在进行的对话。

设置页可切换深色 / 浅色外观与六种主题色(天蓝 / 青色 / 翡翠 / 靛紫 / 琥珀 / 玫红),
并能配置 VLM(视觉语言模型)用于从单价截图识别价格。价格表按渠道计价:一行一个
「来源 · 渠道 · 模型」,同一个模型经不同渠道提供就各填各的价、互不合并;每行一个
识别窗口,粘贴截图后识别结果只预填该行,互不影响(保存前请逐项核对)。

应用内**只存人民币 ¥ / 1M tokens**,行上不标币种。唯一的自动折算发生在识别截图时(「识别」列
表头的 `($→¥)` 就是这个意思):识别到截图上是 $,价格表页会按你填的「1 美元 = ? 人民币」折成
人民币再预填(汇率没填则拒绝预填,不替你猜市场价);截图上没有任何币种标记,就按人民币原样填,
一个汇率也不乘。手工抄的美元价请自己换算后填数字——界面故意不做行内折算按钮:应用无从判断你敲
的 `4` 是 $4 还是 ¥4,一键乘汇率迟早把人民币行乘成假数。汇率只在录入期使用、不参与成本计算,
也**没有内置默认值**。

价格表每行除四档单价外还有两列:只读的「**现总价**」= 已保存单价 × 该渠道已发生用量(与总览
同源,改完单价要保存才刷新),以及可填的「**买断价 ¥**」= 为这个渠道一次性付过的套餐钱。
总览因此并排报两个数:**按量消耗**与**买断支出**,**永不相加**——一个是正在烧的钱,一个是
已经付掉的钱。买断价留空与填 0 严格区分(显示 `—` 与 `¥0.00`),也不摊成每百万等效单价;
总览的「买断支出」同样区分:价格表里一条买断行都没有时显示「**未填**」,有行填了 0 才显示
`¥0.00 · 免费套餐`。

## 快速开始

```bash
make install                          # 后端 + 前端依赖 + pre-commit 钩子
cp pricing.example.json pricing.json  # 可选:启用成本折算(人民币 ¥ / 1M tokens)
make build-web && make dev            # 生产形态:单进程 http://127.0.0.1:8000
# 或前端热更开发:make dev-all(页面在 http://127.0.0.1:5173)
```

## 边界

- 仅统计本机、且自 ZCode 启用该数据库(2026-08-25)以来的记录;账号级总量请查看服务商 dashboard。
- 无公开定价的模型(如内部模型)默认只显示 token 数,不折算金额。
- `pricing.json` 的键是渠道三元组 `source|provider_id|model_id`(整键可从价格表页复制),
  成本从不跨渠道合并;早期以裸 model_id 为键的条目不再命中,价格表页会标为「旧格式键」,
  请按渠道重填后保存。
- token 四档互斥:输入 / 输出 / 缓存写 / 缓存读 相加即总计,「输入」只算未命中缓存的部分,
  缓存命中的 token 只在缓存档计一次。各家口径不同(ZCode 把缓存前缀算在 input 里,opencode 与
  MiniMax 分档独立),归一在各自适配器完成,成本公式只认互斥的四档。
- 存储与显示只有人民币一种币种:`fx_usd_cny` 仅在录入时把美元价折成人民币,不参与成本计算,
  也没有内置默认值(宁可让你填,也不替你猜市场价)。API 的成本字段用中性名 `estimated_cost`,
  不声称币种,由界面标注 ¥。
