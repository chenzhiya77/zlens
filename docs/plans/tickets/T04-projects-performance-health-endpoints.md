# T04 — 按项目 + 性能 + 健康度端点

**Blocked by:** T01 — 最小数据通路:meta + 总览(token 口径)
**Status:** ready-for-agent

## User story

作为关注体验与稳定性的用户,我想拿到按项目拆分的用量、耗时与首字延迟的分位数、以及重试与错误的分布数据——这三组是 zlens 区别于现有工具的差异化视角。

## What to build

三组只读查询端点:按项目(请求粒度表关联会话表的目录/标题聚合)、性能(duration 与 TTFT 的 P50/P90/P99,整体与可选按模型细分)、健康度(重试计数与比例、错误类型/错误码分布、context 超限计数、用户取消计数)。fixture 补充边界样本:TTFT 空值记录、各类错误行、无项目信息的会话。

## Acceptance criteria

- [ ] 性能端点返回三档分位数,TTFT 分位数自动排除空值并在响应中携带有效样本数
- [ ] 无项目归属的请求有明确归类(不丢失、不冒充某项目)
- [ ] 健康度端点的各计数器在含重试/错误/context 超限/取消的合成数据上逐一断言正确
- [ ] 新增端点均有离线测试;`make check` 全绿

## Architectural decisions

- **空值排除而非补零**:TTFT 缺失的请求若按零计入会人为压低分位数;因此排除并暴露样本数,让可信度可见。此口径来自设计会话对"诚实展示"的要求。
