# T05 — 前端壳 + 总览视图页

**Blocked by:** T02 — 价格表与成本估算接入总览
**Status:** ready-for-agent

## User story

作为用户,我启动服务后打开浏览器,看到一个带导航的页面,总览视图以数字卡片呈现请求总数、五类 token 与估算金额——zlens 第一次以"产品"而非接口的形态出现。

## What to build

前端应用骨架与第一条页面链路:Vite + React + TypeScript + Tailwind + shadcn/ui + ECharts + react-query(pnpm 管理);全局布局与六视图导航(未实现的视图显示占位态);开发期将 API 请求代理到本地 FastAPI 端口;总览视图消费 meta + overview 数据渲染数字卡片(含"估算"标记、数据覆盖范围说明);生产构建产物交由 FastAPI 静态托管。安装命令与文档同步更新(make install 追加前端依赖安装)。

视觉基调参照 ZCode IDE"使用统计"面板(spec 视觉基准节):KPI 行用"大号数值 + 灰色小标签 + 细分隔线"的横向布局,不用重边框卡片;数值以中文单位(万)格式化;深色主题、圆角分区、充分留白。

## Acceptance criteria

- [ ] 开发模式:前端开发服务器与后端同时运行,页面经代理取数正常渲染
- [ ] 生产模式:仅启动后端单进程,访问同一端口看到构建后的完整页面
- [ ] 总览卡片数值与对应 API 响应一致;未计价模型在页面上有可辨识的"未计价"呈现
- [ ] KPI 行采用大号数值 + 灰色小标签 + 细分隔线的横向布局,数值以中文单位(万)格式化
- [ ] 未完成视图点击进入显示统一占位态而非报错白屏
- [ ] `make check` 全绿(含前端构建纳入检查流程)

## Architectural decisions

- **交付形态锁定单进程**:浏览器永远只面对自家端口;这决定了静态托管路径属于本票验收而非可选优化。
