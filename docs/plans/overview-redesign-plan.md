# 总览页改版实施计划

> 规格来源：`docs/specs/overview-redesign-spec.md`（已定稿，Q1–Q6 + 3 项追加决定全部落地）
> 设计稿：Ardot `719793184410961`「AI用量总览-优化版」
> 计划日期：2026-08-29 · 票号区间：**T14 – T25**

## 目标

把 Ardot 设计稿落成 zlens 的总览页。设计稿比现有页面多画了周期选择、环比、来源 chips、
排序、合计行、导出六类交互，其中 **8 项后端能力目前不存在**（最关键的：全站没有任何
日期窗口参数）。照着画布直接写前端，这些控件只会是死控件。

所以分**两阶段**：

- **阶段 A（T23）**：纯视觉替换 —— Header / Hero 主指标卡 / 5 张 KPI 卡 / 模型明细表，
  全部走现有字段，**零后端改动**，改完立刻能看到效果。
- **阶段 B（T15–T22、T24）**：后端补齐能力，再把交互控件接上去。

两阶段之间不耦合：T23 不依赖任何后端票，可以和后端并行开工。

## 关键前提：不需要新建设计 token

设计稿的配色（`#fafafa` 底 / `#f4f4f5` 卡片 / `#e4e4e7` 边框）与本项目
`frontend/src/index.css` 里 `html[data-mode="light"]` 翻出来的 zinc 色阶**几乎完全一致**。

也就是说：**设计稿就是现有 zinc token 在 light 模式下的呈现**。T23 用 `bg-zinc-900` /
`border-zinc-800` / `text-zinc-500` 这些现有类去搭结构即可，两种主题自动都成立，
**不需要改全局默认主题，也不需要新建色板**。

## 跨票约束（每一票都要遵守）

- **所有聚合仍在后端**：来源过滤、窗口、排序、合计、环比、命中率、月度聚合全部由 API 出结果。
  前端只做格式化与纯客户端的搜索/别名。这条是 AGENTS.md「现总价一律从 `/api/overview` 取，
  禁止在前端重算一份公式」的延伸。
- **null 的三种表情要分清**：未计价（null）→ 「未计价」/ 空值；未填（null）→「未填」；
  真 0 → 正常显示并附说明。**任何一处把前两者画成 0 都是 bug。**
- **适配器只读不变**：窗口下推不改变 `mode=ro` 约束，不新增任何写入路径。
- **缺省参数 = 今天的行为**：所有新参数都必须有默认值，且默认值下既有测试零改动通过。
- **功能与修复必须带测试**：`tests/` 下新增 `test_<feature>.py`，读真实库打
  `@pytest.mark.live`；推送前 `make check` 全绿。

## 风险与已知问题

- **T15 是全局前置**：它延期会阻塞 T16/T17/T20/T22 四张票。
- **zcode 缓存写恒为 0**（三源实测，见规格 D8）：T21 的 A/B 分母之争在用户当前数据上
  **无差别**，选 A 是给将来买保险。不要因为"现在看不出区别"就跳过。
- **无法证伪的透传风险**：zcode 的 `raw_usage_json` 里 Kimi-K3 有 `cacheWriteTokens` 字段
  但值恒为 0，而 `cache_creation_input_tokens` 列同样恒为 0。只能证明"值恰好是 0"，
  **不能证明 ZCode 会透传非零值**。若将来上游报非零而 ZCode 丢弃，zlens 会静默漏成本。
  今天没有证据，不做处理，但在 D8 留了记号。
- **T23 会改表格列值**：设计稿的表格列值是错位的（把 1.72 亿放进了「输出」列），
  实现时必须按四档互斥口径对齐，**不要照抄画布像素位置**。
