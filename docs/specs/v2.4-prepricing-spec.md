# zlens v2.4 规格：买断（套餐）价格与两个成本总额

> 状态：**已交付** · 定稿：2026-08-27 · 修订：2026-08-28（改成「两列」方案，字段随
> v2.3 的人民币基准改用中性名）· 前置：v1 / v2 / v2.3（见 `v1-spec.md`、
> `v2-multi-source-spec.md`、`AGENTS.md` 的「基准币种人民币」红线）
> 实施票：T14（单票交付）

## Problem Statement

zlens 的价格表原本只有「按量后付」一种口径：input/output/cache_read/cache_write 四档，
成本 = 单价 × 用量。但真实世界里有大量**买断模型**：固定金额买定量额度，钱在购买时一次性
付清，后续请求不再逐笔按单价扣费。现有结构无法表达这种模型——硬塞四档要么算出错误的
「每百万单价」，要么假装每笔请求都在扣钱。

真实数据里这个问题已经显形：一份 15 行的价格表中有 10 行四档全为 0，覆盖全部 token 的
六成。它们混着三种意思——真免费、已含在套餐里、还没填价——却都显示成 `¥0.00`，于是
「总成本」读起来像「这六成用量不要钱」。

用户的真实心智是：**买断模型「花掉的成本」就是买入时付的那笔钱**，一次性、恒定，而不是
消耗出来的。zlens 需要让用户为买断渠道填「买入金额」，并让成本口径诚实地回答两个不同的
问题：**当前按量消耗了多少钱** 与 **买断一共花了多少钱**。

## Solution

价格表每行在四档单价之外新增**两列**（不是新的计价模式，也不是枚举开关）：

- **买断价 ¥**（可空，用户填）：为该渠道一次性付过的钱。留空 = 这行不是买断；填 0 =
  明确就是 0。
- **现总价**（只读，派生）：按**已保存**的四档单价 × 该渠道已发生的用量算出，与总览同源。

总览成本区改为**两个总额并排**，分别回答用户区分过的两个问题：

1. **按量消耗** = Σ 各渠道（单价 × 用量）。继续守「任一服务中的渠道未计价则总额置空」
   那条规则。买断价**不**计入。
2. **买断支出** = Σ 已填写的买断价。它不守上面那条规则——已经付掉的钱不会因为某个渠道
   缺单价而变成未知。

两个数字永不相加。买断行与按量行并排显示即可自解释：`现总价 ¥0.00 ｜ 买断价 ¥299`。

## Implementation Decisions

- **单一可空字段** `ModelPrice.buyout_amount`（人民币）。没有 `billing` 枚举，因此既有
  `pricing.json` 缺该字段即 `null`，零迁移。
- **null 与 0 必须可区分**：界面分别显示 `—` 与 `¥0.00`。否则「没填」会伪装成「免费」，
  正是本票要消灭的那个歧义。
- **买断价不参与任何逐笔成本计算，也不摊成每百万等效单价**：延续「不硬编错价」的红线。
  摊出来的包均价是假精确，还会诱使读者把买断行与按量行放一起比大小。
- **现总价不进 `pricing.json`**：输入（价格表）与输出（成本）不混存。前端从
  `/api/overview` 的 `by_model` 按渠道三元组键（`source|provider_id|model_id`）取
  `estimated_cost` 显示——与总览同源，避免同一公式在前后端各写一份。
- 因此**现总价反映已保存的单价**：改完数字需保存才刷新，页顶与表头悬停都写明。
- **`Overview.buyout_total` 由成本层填**（`enrich_overview`），适配器不产出该字段：它是
  价格表的属性，不是用量的属性。
- **校验只有一条**：`buyout_amount` 非负（沿用现有 `PUT /api/pricing` 的 422 语义）；
  `null` 合法。
- **未计价逻辑不变**：价格表里有该渠道条目（哪怕四档全 0 或只有买断价）即视为已表态，
  不进 `unpriced_models`。
- **截图识别不涉及买断**：VLM 只提取 token 单价，提示词本就要求忽略套餐/订阅类金额。
- **相对上一版 spec 放弃的东西**：`billing` 三态开关、`prepaid_tokens`（买入量）与
  「已用/剩余」显示、买断行隐藏四个单价格。理由：两列并置已经自带解释，模式开关换来的
  状态与校验不划算。已知残留歧义：「真免费」与「还没填价」在按量侧都显示 `¥0.00`，
  只能靠旁边的买断价列旁证。

## API Contract 变更

- `GET/PUT /api/pricing` 的 `ModelPrice` 增加 `buyout_amount?: number | null`。
- `GET /api/overview` 增加 `buyout_total: number`（无买断行时为 0）。
- `estimated_cost` 语义不变 = 按量消耗；字段一律用中性名、不声称币种（v2.3 已把
  `estimated_cost_usd` 改名为 `estimated_cost`，本票不再引入 `*_usd` 这类会说谎的名字）。

## Testing Decisions

沿用唯一 seam（HTTP API + fixture 库），新增用例：

- `buyout_amount` 逐渠道往返保存；未填的行回落为 `null` 而不是 0；
- 买断价为负 → 422；纯按量条目不受影响；
- `buyout_total` 只累加已填金额：没填的行不计、没有用量的买断渠道照计、存在未计价渠道时
  `estimated_cost` 仍为 null 而 `buyout_total` 仍正确；
- 买断价绝不进入逐笔成本（同一行加了买断价后 `estimated_cost` 不变）。

## Out of Scope

- 买入量与剩余量（`prepaid_tokens`）：用户通过服务商订单得知购买总数，zlens 不复制一份
  会过期的账；
- 超量后转按量（买断额度用完继续按单价计费）；
- 包均价摊销、买断与按量的「等效单价」对比视图；
- 自动识别「这张截图是买断价还是按量价」。

## Further Notes

- 用户方案原文：买断模型由用户在价格列表的「买入」列填金额。本 spec 把它落成
  `buyout_amount` 一列，并补上「现总价」这一派生列作为改价后的即时反馈。
- 诚实原则贯穿：已付的钱与烧掉的各说一个数，不合并、不摊销、不假装精确。
